# GitHub presentation checklist

Use these settings on the GitHub repository page so the portfolio entry looks complete beside the README.

## About panel

Description:

> Anonymized Laravel + React education operations platform case study featuring admin dashboards, enrollment workflows, demo conversion analytics, teacher tools, showcases, email automation, and secure media.

Suggested topics:

```text
laravel, php, react, typescript, rest-api, eloquent, admin-dashboard,
crm, booking-system, email-automation, full-stack, case-study
```

Recommended settings:

- Keep the repository public only after reviewing the complete commit history.
- Add the website/demo URL only if it is a sanitized portfolio URL, never the client domain.
- Keep Releases and Packages empty unless this repository later contains a public distributable.
- Pin the repository on your profile after adding the About description and topics.
- Use a short commit history with meaningful messages such as `docs: add anonymized platform case study` and `assets: add sanitized admin workflow visuals`.

## README review

Before publishing, confirm the first screen communicates:

1. What the product is.
2. What you personally delivered.
3. Which technologies and integrations were used.
4. What the admin workflows look like.
5. Why the production source is private.

Do not add client URLs, real screenshots, private names, live credentials, database exports, or copied production content.
